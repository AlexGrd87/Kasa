01Vue d'ensemble

Kasa est une application de location de logements : une page d'accueil qui liste les biens, une page à propos, et une page détail par logement. Les données viennent d'un fichier JSON statique (pas d'API), et tout le style est écrit en Sass.

Structure des dossiers

src/ components/ Header, Footer, Banner, Card, Collapse, Slideshow layouts/ Layout.jsx (Header + contenu + Footer) pages/ Home, About, Housing, Error router/ Router.jsx (toute la logique de routage) data/ logements.json styles/ _variables.scss (couleurs, tailles partagées)

02Concepts clés

Les notions React que le jury peut te demander de justifier, chacune reliée à du code réel du projet.

Props

Un composant reçoit des données de son parent via des props — il ne les modifie jamais, il les affiche.

Pourquoi : Card est utilisé 20 fois avec des données différentes, sans dupliquer de code.
const Card = ({ id, title, cover }) => (
  <Link to={`/housing/${id}`} className="card">
    <img src={cover} alt={title} />
    <p>{title}</p>
  </Link>
);

useState

Un hook qui donne à un composant une mémoire locale : une valeur qui, quand elle change, redéclenche l'affichage.

Pourquoi : le Collapse doit se souvenir s'il est ouvert ou fermé, et le Slideshow de quelle image est affichée.
const [isOpen, setIsOpen] = useState(false);

const toggle = () => setIsOpen(!isOpen);

Listes & clés

map transforme un tableau de données en tableau de composants JSX. React exige une prop key unique et stable sur chaque élément généré.

Pourquoi : sans key, React affiche un warning console — interdit par le cahier des charges.
{logements.map(({ id, title, cover }) => (
  <Card key={id} id={id} title={title} cover={cover} />
))}

React Router

Gère la navigation sans recharger la page. Une route peut être statique (/about), dynamique (/housing/:id) ou universelle (* pour le 404).

Pourquoi : useParams() récupère l'id dans l'URL pour retrouver le bon logement dans le JSON.
<Route path="/housing/:id" element={<Layout><Housing /></Layout>} />
<Route path="*" element={<Layout><Error /></Layout>} />

Sass

Un langage qui compile vers du CSS classique, avec des variables, de l'imbrication de sélecteurs et des fichiers partiels importables.

Pourquoi : les couleurs et tailles (comme le corail #FF6060) sont définies une seule fois dans _variables.scss, réutilisées partout.
@use '../../styles/variables' as *;

.card__title {
  color: $color-text-light;
}

05Git & GitHub

Une branche par étape du cahier des charges, une pull request, un merge — pour un historique lisible.

git checkout -b feature/etape-X → commits → gh pr create → gh pr merge --merge

Résultat : 9 pull requests mergées dans main, une par étape (2 à 10 — l'étape 1 est le commit initial). Chaque PR a un titre et une description qui expliquent ce qu'elle apporte.

06Questions probables du jury

Pourquoi avoir découpé Collapse en composant séparé plutôt que de dupliquer le code ?

Il est utilisé 6 fois (4 sur About, 2 sur Housing) avec un comportement identique : le dupliquer aurait multiplié les bugs à corriger. Un seul composant, une seule source de vérité.

Comment gères-tu un id de logement qui n'existe pas dans l'URL ?

logements.find() retourne undefined si aucun logement ne correspond. Dans ce cas, le composant retourne <Navigate to="/404" replace />, qui redirige immédiatement vers la page d'erreur.

Comment fonctionne la navigation circulaire du carrousel ?

Le calcul (index - 1 + longueur) % longueur pour "précédent" et (index + 1) % longueur pour "suivant" fait boucler l'index automatiquement, sans jamais sortir des bornes du tableau.

Pourquoi utiliser Sass plutôt que du CSS classique ?

Les variables (couleurs, tailles) sont centralisées dans un seul fichier et importées partout avec @use — un changement de couleur de marque se fait à un seul endroit plutôt que dans chaque fichier CSS.

As-tu vérifié qu'il n'y a pas de warning dans la console ?

Oui, systématiquement après chaque étape, y compris sur les cas limites (logement à une seule image, id invalide, navigation entre les 4 pages).
